# Specimen test photos

Fictional, generated test photos for the "Before You Share" Skill: the **Beach day** album (B01 to B12) and the
**Hazard set** (H01 to H10) described in `skill/before-you-share/references/validation-plan.md`. The table of every
image, its planted risk, position and expected verdicts is in [MANIFEST.md](MANIFEST.md).

## Regenerate

Requires Python 3 and Pillow (`pip install Pillow`). From the repository root:

```sh
python tests/specimens/generate.py      # or: npm run specimens
```

This rewrites:

- `tests/specimens/beach-day/` and `tests/specimens/hazard-set/`: the originals (1600x1200 JPEG, quality 82;
  H09 is a 1170x2532 PNG screenshot) with EXIF;
- `tests/specimens/MANIFEST.md`;
- `docs/assets/specimens/`: web copies (640 px wide, the screenshot 320 px, JPEG quality 70, EXIF removed) and
  `manifest.json` for the website.

The generator is deterministic: fixed seeds, fixed EXIF dates (2025-07-19), no timestamps. A re-run with the same
Pillow version and fonts gives byte-identical files; the script prints a SHA-256 digest of all images so two runs can
be compared. It uses DejaVu fonts when available (other systems may fall back to Arial, Liberation or Pillow's
built-in font, which changes pixels but not content). It also reads the EXIF back from every file and stops with an
error if a planted field (GPS on B01; owner, copyright and serial on H10) is missing or appears where it should not,
if a finding lands in a different grid cell than `report-format.md` expects, or if the verdict counts no longer match
the validation plan.

## Testing day

1. Upload all 22 originals from `beach-day/` and `hazard-set/` (not the web copies, which have no EXIF) into the
   **personal photo library** of the NAS account under test.
2. Create the album **"Beach day"** from B01 to B12. Leave the Hazard set as loose photos (or an album "Hazard set").
3. Wait until the photo library shows text and object recognition on the uploaded photos, then run the test cases in
   `validation-plan.md` in order.
4. For **test 11** (shared-album audit), create an album containing **B07** and **H01** and share it with another
   NAS account; run the audit for audience Public and confirm the album is left unchanged.
5. For a real-photo variant, print the props (H01 ID card, B09 boarding pass, H03 package label, H02 payment card,
   H05 Wi-Fi note, H07 prescription label) from these files and photograph them with a phone; the expected verdicts
   stay the same. Drawn faces are unreliable for vision models and for the NAS face index, so re-shoot **H08** as a
   real phone photo with consenting people (one subject close to the camera, two people further back) and keep the
   drawn H08 only as a fallback.
6. Remove the uploaded specimens and the test albums after the testing window.

## Safety

Everything here is fictional and generated by code: no real person, face, address, plate, document, card, booking or
password. Names, places and companies are invented (Republic of Exemplia, Lakeside, Harbor St, Exemplia Air,
Exemplia Bank); the card number is all zeros; no real government, airline or bank design or logo is imitated. Every
file carries `SPECIMEN` in its EXIF ImageDescription, and every photo with a planted visual or location risk also has
a small visible SPECIMEN mark. The GPS position in B01 is a public beach (Barceloneta beach area), not a home. The
Wi-Fi key and codes shown are test values only; never reuse them for a real network or account.
